- **Result**: every scenario across all four `.feature` files passes (29

  No spec, feature, or `GUARANTEES.md` gap was found that required a
  change — closing the same two implementation-technique questions the
  TypeScript generation (`blueprint/lineage/0002`) surfaced, but this time
  without needing new spec text, since the specs already dictated the
  desired behavior and only the implementation technique was in question:
  (1) Rust's `url` crate (also a WHATWG URL Standard implementation) has
  the same quirk as JavaScript's `URL`: it silently strips ASCII tab/CR/LF
  from input rather than rejecting it (verified empirically, not assumed —
  `url::Url::parse("https://example.com/a\r\nb")` succeeds with the CR/LF
  removed). Control-character rejection is therefore implemented as an
  explicit pre-check on the raw string in
  `rust/src/modules/url_creation.rs`, before the string ever reaches
  `url::Url::parse`. (2) The redirect `Location` header
  (`blueprint/decisions/ADR-0007-location-header-preserves-percent-encoding.md`)
  is built by percent-encoding only the specific characters unsafe for HTTP
  header transport on the raw `original_url` string (`rust/src/modules/redirect.rs`),
  not by re-serializing through `url::Url::as_str()` — the latter was
  tried first and rejected because it introduces normalization beyond
  percent-encoding (lower-cased scheme, an added trailing slash for an
  empty path) that the ADR's "percent-encoding-equivalent" wording doesn't
  license. One thing was verified rather than assumed and required *no*
  fix, unlike TypeScript: Rust's `str::chars()` already iterates Unicode
  scalar values (code points), so the 2048-character length limit in
  `blueprint/specs/url-creation.md` is correct by construction — there is
  no UTF-16-surrogate-pair double-counting risk to guard against in Rust,
  confirmed by the "Length limit counts Unicode code points, not UTF-16
  code units" scenario test passing with zero extra code beyond
  `.chars().count()`. Implementation choice (noted for context only, not
  binding on future regenerations): Axum 0.7 + Tokio, the `url` crate for
  request-time URL parsing/validation, `percent-encoding` for the
  `Location` header, `chrono` for timestamps, `rand` for code generation,
  an in-memory store behind a single `std::sync::RwLock<HashMap<...>>`,
  `cargo test` + `proptest` for tests. No known open gaps as of this
  entry.
